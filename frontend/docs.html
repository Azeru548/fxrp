@rowan/fxrp-pay-sdk

Accept FXRP payments. Typed, on-chain, no server.

This is the developer guide for Rowan: the TypeScript SDK, the payment-link format, USD→FXRP pricing math, and the FxrpPay contract. Use it to invoice in dollars, settle in FXRP on Flare, and withdraw to a merchant address you control.

01 · Overview

What Rowan is

Rowan is a payment rail for FXRP on Flare. A merchant creates an invoice priced in USD cents or a fixed FXRP amount. A payer opens a payment link, approves the token, and pays. The USD→FXRP conversion happens on-chain at payment time using Flare FTSOv2’s XRP/USD feed. Settled tokens sit in the contract until the merchant withdraws.

There is no Rowan server, no API key, and no custodian. The public contract is the product. The SDK is a typed wrapper around that contract so you do not hand-roll approvals, oracle fees, or link parsing.

  • Contract — FxrpPay.sol, Solidity 0.8.20+, zero imports, Remix-compilable.
  • Three writes — createInvoice, pay, withdraw (plus cancelInvoice).
  • Payment link — #/pay?c=<FxrpPay address>&id=<invoice id> is the drop-in checkout URL.
  • SDK — @rowan/fxrp-pay-sdk in sdk/: TypeScript, ESM + CJS, ethers v6 peer dependency.
Status. Live on Flare Testnet Coston2 with a mock FXRP token. The SDK is shipped from this repository (build with npm run sdk:build). It is not on the public npm registry yet; install from the local sdk/ path. Songbird and Flare Mainnet use the same bytecode with a real FXRP address.

02 · Architecture

How the pieces fit

A Rowan integration has four moving parts. You can use all of them, or only the contract.

PieceRoleYou run?
FxrpPayStores invoices, prices USD via FTSOv2, pulls ERC-20, holds funds, pays out to the payee.No — already deployed on Coston2, or you deploy your own.
Payment tokenThe ERC-20 the invoice is paid in. Demo uses MockFXRP. Production uses FXRP (FAsset).No on Coston2 demo; Mainnet uses the canonical FXRP.
FTSOv2On-chain XRP/USD oracle. Only used for PRICING_USD invoices.No — Flare protocol.
SDK / appWallet connection, approve-and-pay, link helpers, price preview.Your app, or the static Rowan frontend.

Reads (invoice state, due amount, XRP/USD) work against a public RPC with no wallet. Writes need an EIP-1193 provider or an ethers Signer.

Money flow

  1. Merchant createInvoice(payee, token, pricing, amount, memo) → invoice id.
  2. Merchant shares #/pay?c=…&id=… (or uses the SDK link field).
  3. Payer approves the token, then pay(id). For USD invoices, msg.value covers the FTSOv2 fee; excess FLR is refunded in the same transaction.
  4. Contract pulls exactly the remaining due via transferFrom and auto-closes when paid ≥ target.
  5. Payee withdraw(id) to pull the collected balance.

03 · Concepts

Invoices, pricing, custody

Invoice

An invoice is a row in the contract: payee, token, pricing mode, amount, running paid, open flag, and memo. The id is the array index, assigned sequentially from 0.

FieldMeaningEncoding
payeeMerchant who may withdraw. Immutable after create.address
tokenERC-20 the payer must hold. Demo default is MockFXRP.address
pricingHow amount is interpreted.0 = fixed token units · 1 = USD cents
amountInvoice face value in the pricing mode.token wei (0) or integer cents (1)
paidToken units collected so far.18-decimal token units
openAccepting payments. False after full pay or cancel.bool
memoHuman note shown in the app.string

USD vs fixed

USD invoices do not lock an FXRP amount at creation. The target is computed when pay runs, from the live FTSOv2 price, ceiling-rounded. That means the FXRP due can move between “create” and “pay.” Preview with usdCentsToTokens; settle with getDue(id).

Fixed invoices store a token amount. No oracle call, msg.value must be 0.

What “pay remaining” means

Each pay pulls the full remaining due at that transaction’s price — not an arbitrary partial. After a successful USD payment the invoice typically closes in one shot. getDue returns 0 when the invoice is closed.

Custody

Tokens are held by FxrpPay, not by Rowan and not by a merchant hot wallet until withdraw. Only payee can call withdraw or cancelInvoice. There is no admin, pause, or upgrade key on the demo contract.

04 · Install

Install the SDK

Peer dependency: ethers v6. Node 18+ recommended. The package lives at sdk/ in this repo.

From this repository

bash # in the Rowan / fxrp-pay repo npm install npm run sdk:build # in your app npm install ethers@^6.0.0 /absolute/path/to/fxrp-pay/sdk

After publish the one-liner will be:

bash npm install @rowan/fxrp-pay-sdk ethers

What you get

  • dist/esm — ES modules (import)
  • dist/cjs — CommonJS (require)
  • dist/esm/index.d.ts — TypeScript types
  • sdk/abi/FxrpPay.json — machine-readable ABI if you skip the client

Repo scripts: npm run sdk:build, npm run sdk:gen-abi, npm run sdk:smoke (live Coston2 reads, no gas).

05 · Quickstart

The three-call loop

typescript import { FxrpPayClient, PRICING_USD } from "@rowan/fxrp-pay-sdk"; // 1. Merchant creates a $49.99 invoice const merchant = await FxrpPayClient.fromBrowserProvider(window.ethereum); const { id, link, txHash } = await merchant.createInvoice({ pricing: PRICING_USD, amount: "4999", // USD cents → $49.99 memo: "Order #1234", }); // link === "#/pay?c=0x29A6…aff72&id=7" // 2. Payer opens the link (or you pass the id) and pays const payer = await FxrpPayClient.fromBrowserProvider(window.ethereum); const paid = await payer.pay(id); // approve + oracle fee handled console.log("paid", paid.totalPaid, paid.txHash); // 3. Merchant withdraws settled FXRP await merchant.withdraw(id);
Read-only without a wallet. new FxrpPayClient() talks to the public Coston2 RPC. Use it on a backend to poll getInvoice / isPaid.

07 · API

Method reference

createInvoice(params) — signer required

Creates an invoice and returns the id plus a relative payment link. payee defaults to the signer; token defaults to Coston2 MockFXRP; pricing defaults to USD.

typescript const { id, link, txHash, receipt } = await client.createInvoice({ payee: "0xMerchant…", // optional token: "0xFXRP…", // optional, MockFXRP on Coston2 pricing: PRICING_USD, // or PRICING_FIXED amount: "2000", // 2000 cents = $20.00 · or token wei if fixed memo: "August retainer", });

amount is bigint | string. For USD, pass integer cents ("4999" or 4999n), not a dollar float. For fixed FXRP, pass raw 18-decimal units (or build them with parseUnits from ethers). Reverts in-SDK if amount <= 0.

The id is parsed from the InvoiceCreated event. If the event is missing, the client throws Could not determine new invoice id from receipt.

pay(id, options?) — signer required

Loads the invoice, refuses closed/already-paid ones, approves the token if allowance < due (max uint256), sends oracleFee() as msg.value for USD invoices, waits for confirmation, and returns a PayResult.

OptionDefaultDescription
approvetrueSet false if you already approved.
valueoracle fee or 0nOverride msg.value in wei.
typescript const result = await client.pay(4, { approve: true }); // { id, payer, amount, totalPaid, tokenDecimals, txHash, receipt }

withdraw(id) / cancelInvoice(id) — payee signer

withdraw transfers the full paid balance to the payee and zeroes the stored paid amount. The contract reverts with only payee / nothing to withdraw.

cancelInvoice sets open = false. It does not move tokens. Returns the transaction hash string.

Reads — no signer

MethodReturns
getInvoice(id)InvoiceView including derived due and isPaid.
getDue(id)Remaining token units. 0 if closed.
isPaid(id)Contract view: closed and paid ≥ current target.
oracleFee()FTSOv2 fee in wei (0 on Coston2 for this feed).
getXrpUsdPriceWei()Price as 18-decimal bigint.
getXrpUsdPriceUsd()Same price as a JS number (lossy; UI only).
tokenDecimals(address?)ERC-20 decimals, or 18 if the call fails.
About isPaid. The contract recomputes the USD target from the current oracle price. After withdraw, paid is zero, so isPaid becomes false. For “was this invoice settled?” prefer events (InvoiceClosed / PaymentReceived) or your own record of the pay transaction.

09 · Payment links

The integration URL

The Rowan app routes on the hash. Any site can mint the same URL and send the payer to the hosted app (or your fork).

format #/pay?c=<FxrpPay address>&id=<invoice id>
typescript import { buildPaymentLink, parsePaymentLink, PAY_ROUTE } from "@rowan/fxrp-pay-sdk"; const relative = buildPaymentLink(FXRP_PAY_COSTON2, 7); // "#/pay?c=0x29A6…&id=7" const absolute = buildPaymentLink( FXRP_PAY_COSTON2, 7, "https://azeru548.github.io/fxrp/" ); // "https://azeru548.github.io/fxrp/#/pay?c=0x29A6…&id=7" const parsed = parsePaymentLink(absolute); // { contractAddress, id: 7n } or null if the hash is malformed

parsePaymentLink looks for #/pay anywhere in the string, then reads c and a numeric id. Missing or non-numeric id → null.

The hosted app pre-fills contract + id from that hash and opens the Pay tab. Keep the format stable if you build your own payer UI.

10 · Pricing

USD → FXRP math

The contract converts cents to 18-decimal token units with ceiling division so the merchant is never paid short:

solidity usdWei = usdCents * 1e16 // cents → 18-dec USD tokens = ceil(usdWei * 1e18 / xrpUsdWei) = (usdWei * 1e18 + price - 1) / price

The SDK mirrors that exactly. Do not reimplement with floats.

HelperExample
parseUsdToCents(input)"$49.99" → 4999n. Also accepts 49.99.
formatUsdCents(cents)4999n → "$49.99"
usdCentsToTokens(cents, priceWei)Ceiling-rounded token units.
tokensToUsdCents(tokens, priceWei)Floor-rounded inverse.
formatTokenUnits(units, decimals?)"49.943" style display via ethers formatUnits.
typescript import { parseUsdToCents, usdCentsToTokens, formatTokenUnits } from "@rowan/fxrp-pay-sdk"; const cents = parseUsdToCents("$50.00"); // 5000n const price = await client.getXrpUsdPriceWei(); const due = usdCentsToTokens(cents, price); console.log(formatTokenUnits(due), "FXRP (estimate)");
Show getDue(id) at confirm time. A preview can be a block stale. The wallet will pull whatever the contract computes in pay. Oracle fee is separate (FLR / C2FLR), not FXRP.

USD mode assumes an 18-decimal token that tracks XRP (FXRP). Do not point a USD invoice at USDC or a 6-decimal token — the oracle is always XRP/USD.

11 · Errors

SDK throws and contract reverts

Client-side

  • FxrpPayClient: a signer is required for write calls
  • amount must be > 0
  • Invoice is not open / Invoice is already paid (preflight in pay)
  • Could not determine new invoice id from receipt
  • Invalid USD amount from parseUsdToCents
  • XRP/USD price must be > 0 from pricing helpers

14 · Security

Notes for integrators

  • Approvals. Default SDK path is infinite allowance to FxrpPay. For tighter threat models, approve exactly due and pass { approve: false } after you did it yourself.
  • Payee is forever. Wrong merchant address cannot be patched. Default to the connected signer unless you have a dedicated treasury.
  • Token address. USD pricing always uses XRP/USD. Only use 18-decimal FXRP (or the Coston2 mock) in that mode.
  • Oracle fee. Always read oracleFee(). It is 0 on Coston2 for this feed; it will not stay 0 everywhere.
  • Reentrancy. pay and withdraw are guarded. FLR refund happens before the ERC-20 pull, still inside the guard.
  • No pause / no upgrade. Treat the contract as immutable. If you need rescues, that is a different design.
  • Testnet token. MockFXRP is freely mintable. It is not FXRP.
  • Verify settlement off events. Index PaymentReceived / InvoiceClosed rather than trusting a later isPaid call after withdraw or a price move.

16 · FAQ

Developer FAQ

Can I call the contract from viem / wagmi?

Yes. Use sdk/abi/FxrpPay.json. You must still approve the token, send oracleFee() as value on USD pays, and parse InvoiceCreated for the new id. The SDK is ethers-only.

Does createInvoice cost FXRP?

No. Creation is a state write. The payer spends FXRP (and possibly a tiny FLR oracle fee) at pay time.

Can two people pay the same invoice?

The first successful pay usually closes it. A second pay reverts invoice closed. There is no split-the-bill helper in this version.

How do I list a merchant’s invoices?

The contract has no index by payee. Scan InvoiceCreated from the deploy block, or keep ids in your database when you create them. That is the intended integration for a shop backend.

Is the SDK published to npm?

Not yet. Install from the sdk/ folder after npm run sdk:build. Package name is reserved as @rowan/fxrp-pay-sdk.
